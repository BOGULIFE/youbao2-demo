# PRD: FR-022 首页金刚区与点击分析

## 0. Document Purpose

本 PRD 定义右豹创作者 App 首页金刚区及其运营配置、点击统计、后台报表和数据导出能力，供产品、UX、架构、数据和研发使用。FR-022 独立于已定稿的 FR-021，沿用 FR-021 的 Creator BFF、运营后台权限和 C 端首页视觉体系，但不回改 FR-021 定稿合同。截图仅作为现状 UI 参考。

本文采用 Glossary 统一术语，功能按特性分组，FR 使用 `FR-022.x` 稳定编号；事件字段、缓存、幂等和数据模型等实现细节收录在同目录 `addendum.md`。

## 1. Vision

右豹首页承载大量内容和业务模块，用户需要更短路径进入高频功能，运营也需要在不发版的情况下调整入口信息和去向。FR-022 在 Banner 后增加金刚区，把高频功能组织为可配置的快捷入口，让首页从“信息浏览”补足为“快速行动”。

金刚区不是新的业务页面，而是首页入口编排能力。运营保存配置后立即生效，入口的内容、排序、启停和有效期由后台维护；用户点击后进入白名单内的站内页面或受控外部页面。

同时，FR-022 建立入口级点击分析：点击次数按事件累计，点击人数按登录用户去重。后台默认展示累计值，也支持按时间范围查看汇总、趋势和明细，并导出当前筛选结果，为入口运营和后续迭代提供可核对的数据基础。

## 2. Target User

### 2.1 Jobs To Be Done

- **创作者：** 在首页快速识别并进入当前可用的高频功能，不必记住功能所在的多级路径。
- **运营人员：** 在不依赖研发发版的情况下，调整首页入口文案、图标、排序、启停和跳转目标，并立即看到生效结果。
- **运营/数据人员：** 按入口和时间范围核对点击次数、去重点击人数及点击明细，导出数据用于复盘和汇报。

### 2.2 Non-Users (v1)

- 需要复杂人群分层、AB 实验或千人千面的运营人员。
- 需要匿名访客跨设备识别的分析人员。
- 需要在本需求内配置 Banner、榜单、找项目、动态或今日路径内容的运营人员。

### 2.3 Key User Journeys

- **UJ-1. 小周从首页进入高频功能。**
  - **Persona + context：** 小周是已登录的创作者，打开右豹首页准备完成当天的操作。
  - **Entry state：** 已登录，处于首页 Tab，首页接口返回一个或多个有效金刚区入口。
  - **Path：** 查看 Banner 下方的金刚区 → 识别入口图标和标题 → 点击一个入口 → 系统记录点击事件 → 打开配置的站内页面或受控外部页面。
  - **Climax：** 小周不需要经过额外的首页模块或菜单，即可进入目标功能。
  - **Resolution：** 返回首页后仍能看到同一份已生效配置；如果入口已被停用，则不再展示。
  - **Edge case：** 目标失效或无权限时，系统提示原因并留在首页，不影响其他入口。

- **UJ-2. 李姐即时调整首页入口。**
  - **Persona + context：** 李姐是运营人员，需要把一个活动入口提前并暂时停用另一个入口。
  - **Entry state：** 具有首页配置权限，进入后台金刚区配置页面。
  - **Path：** 编辑图标、标题、跳转目标或排序 → 保存配置 → 看到“已保存并生效”反馈 → 刷新或重新进入 C 端首页核对结果。
  - **Climax：** 保存后新配置立即进入线上首页，不需要额外点击发布或等待审批。
  - **Resolution：** 后台保留操作记录；如配置错误，可恢复上一份有效配置。

- **UJ-3. 李姐查看入口效果并导出。**
  - **Persona + context：** 李姐在周报前核对金刚区各入口的使用情况。
  - **Entry state：** 具有首页数据查看和导出权限，进入金刚区数据报表。
  - **Path：** 默认查看累计点击次数和去重点击人数 → 选择入口或时间范围 → 查看汇总、按日趋势和脱敏明细 → 导出当前筛选结果。
  - **Climax：** 报表中的点击次数与去重人数可以按入口和时间范围解释，并能下载留档。
  - **Resolution：** 导出文件与当前筛选条件一致；无数据时显示空态而不是伪造 0 以外的结果。

## 3. Glossary

- **金刚区** — 首页上的快捷入口集合，位于 Banner 后、三格数据前；由后台配置并由 C 端渲染。
- **金刚区入口** — 金刚区中的单个可点击项目，由 `entryId` 唯一标识。
- **有效配置** — 启用状态为开启，且当前时间位于生效时间和失效时间范围内的配置。
- **跳转目标** — 金刚区入口点击后打开的受控站内页面或外部页面。
- **点击次数** — 入口收到的有效点击事件数量；同一用户重复点击按多次计算。
- **点击人数** — 在指定统计范围内按登录用户 `userId` 去重后的用户数量。
- **累计值** — 从统计系统启用时间或入口首次生效时间起，未指定结束时间的累计统计结果。具体起始规则见 §8。
- **时间范围统计** — 按后台选择的开始日期和结束日期计算的统计结果，按 Asia/Shanghai 自然日解释边界。
- **点击明细** — 入口点击事件的脱敏记录，包括入口、时间、配置版本和跳转结果。
- **立即生效** — 后台保存成功后，新的有效配置可被首页 BFF 读取；不需要草稿、发布或审批步骤。

## 4. Information Architecture

### 4.1 C 端首页

FR-021 的首页顺序扩展为：

```text
顶栏 → Banner → 金刚区 → 三格数据 → 新手学院/活动中心
→ 设置工作台 → 榜单 → 找项目 → 右豹动态 → OPC 服务机构 → Footer
```

金刚区不取代 Banner、设置工作台或今日路径气泡，也不改变其余模块的既有职责。

### 4.2 运营后台

FR-022 新增两个后台页面或等价入口：

- **金刚区配置：** 维护入口基础信息、跳转、排序、启停和有效期。
- **金刚区数据报表：** 查看累计或时间范围内的汇总、趋势、明细并导出。

后台页面沿用现有运营后台权限和管理风格。具体菜单位置由架构和现网后台导航在后续阶段确定。

## 5. Features

### 5.1 C 端金刚区展示与跳转

**Description:** C 端首页读取后台下发的有效配置，按排序展示紧凑的快捷入口。第一版使用固定尺寸的宫格布局，避免文案差异导致首页布局跳动。实现 UJ-1。

#### FR-022.1：展示有效金刚区入口

已登录创作者打开首页时，系统展示当前有效的金刚区入口。

**Consequences (testable):**

- 金刚区位于 Banner 后、三格数据前；
- 入口按后台排序升序展示；
- 入口至少展示图标和标题，副标题为可选字段；
- 仅启用且处于有效时间范围内的入口会下发到 C 端；
- 配置为空或所有入口无效时，金刚区整体隐藏，不显示空壳卡片；
- 单个入口内容缺失或非法时，该入口不展示，其他有效入口不受影响。

#### FR-022.2：点击入口并跳转

创作者点击金刚区入口时，系统打开该入口配置的跳转目标。

**Consequences (testable):**

- 站内跳转打开对应页面或详情页；
- 外部跳转仅允许配置白名单内的目标；
- 目标失效、无权限或打开失败时显示统一错误反馈并保留当前首页；
- 点击入口不会触发其他首页卡片、轮播或今日路径气泡的行为；
- 返回首页后金刚区状态与最新有效配置一致。

#### FR-022.3：布局与降级

金刚区在移动端首页以紧凑宫格展示，内容变化不应破坏首页其他模块。

**Consequences (testable):**

- 第一版建议 4 列布局，最多 8 个入口；超过上限的处理方式见 §8；
- 标题最多一行，副标题最多一行，超出文本截断；
- 金刚区数据加载失败时隐藏该模块或使用轻量占位，不阻塞首页其他接口；
- 图标入口提供可读的无障碍名称，不能只依赖图形表达含义。

### 5.2 后台即时生效配置

**Description:** 运营人员在后台维护金刚区入口，保存后立即影响线上首页。配置操作需要校验、审计和可恢复，但第一版不建设草稿/发布流程。实现 UJ-2。

#### FR-022.4：维护入口基础信息

具有权限的运营人员可以新增、编辑和删除金刚区入口。

**Consequences (testable):**

- 支持配置 `entryId`、图标、标题、副标题、跳转类型、跳转参数、排序、启用状态、生效时间和失效时间；
- 标题、图标、跳转类型和跳转参数为必填；
- 保存前校验字段完整性、时间范围和跳转目标合法性；
- 删除或停用后，入口不再作为有效配置下发；
- 同一入口 ID 不产生重复有效记录。

#### FR-022.5：排序与启停

运营人员可以调整入口排序和启停状态。

**Consequences (testable):**

- 排序结果在 C 端按同一顺序呈现；
- 停用入口不展示、不计入新的有效点击入口列表；
- 到达失效时间的入口自动失效；
- 重新启用且处于有效时间内的入口恢复展示。

#### FR-022.6：保存后立即生效

运营人员保存配置后，配置立即生效，不经过草稿、发布、审核或预览版本切换。

**Consequences (testable):**

- 保存成功后返回生效版本号或更新时间，并提示“已保存并生效”；
- 首页在缓存刷新后读取新版本；缓存机制不得造成不可解释的长时间旧配置；
- 保存以原子操作完成，不出现基础信息与跳转参数分裂生效；
- 后台记录操作人、操作时间、变更内容和结果；
- 支持恢复上一份有效配置，恢复操作同样立即生效并留痕。

#### FR-022.7：跳转目标安全控制

后台只允许配置受控跳转类型和合法目标。

**Consequences (testable):**

- 站内路由必须匹配允许的路由清单；
- 外部链接必须匹配允许的 HTTPS 域名清单；
- 非法协议、空目标或未授权域名保存失败并提示原因；
- C 端不执行后台传入的任意脚本或未验证跳转参数。

### 5.3 点击事件上报

**Description:** 每次入口点击产生可追踪事件，支持点击次数累计和按登录用户去重的点击人数。实现 UJ-1、UJ-3。

#### FR-022.8：上报入口点击

C 端在用户点击入口时上报入口 ID、配置版本和用户上下文。

**Consequences (testable):**

- 每次有效点击最多产生一条具有唯一 `eventId` 的事件；
- 事件至少包含入口 ID、配置版本、登录用户 ID、入口位置、点击时间、跳转类型和跳转结果；
- 客户端重试不会造成同一 `eventId` 重复计数；
- 上报失败不得阻塞跳转；客户端允许异步重试；
- 跳转失败仍记录点击，并以独立字段记录失败结果。

#### FR-022.9：点击次数口径

系统按有效点击事件累计入口点击次数。

**Consequences (testable):**

- 同一用户对同一入口的多次点击按多次计数；
- 同一事件因重试、重复消费或重复导入不得重复计数；
- 统计结果可以按入口和时间范围汇总；
- 入口配置修改不改变历史事件归属的 `entryId`。

#### FR-022.10：点击人数口径

系统按登录用户 `userId` 对入口点击人数去重。

**Consequences (testable):**

- 同一入口、同一统计范围内同一 `userId` 只计 1 人；
- 不同入口分别计算人数，同一用户点击两个入口计入两个入口的人数；
- 时间范围变化会重新计算范围内去重人数；
- 第一版未登录用户不纳入点击人数；
- 后台不得用客户端传入的“人数”覆盖服务端计算结果。

### 5.4 后台数据报表与导出

**Description:** 运营和数据人员在后台查看入口效果，默认看累计值，也可按时间范围筛选。报表同时满足快速汇总和可核对明细的需要。实现 UJ-3。

#### FR-022.11：累计统计

报表首次打开时默认展示累计点击次数和累计去重点击人数。

**Consequences (testable):**

- 默认状态不需要用户先选择日期即可查询；
- 汇总按入口展示入口名称、入口 ID、点击次数和点击人数；
- 累计起始规则在报表页面明确展示或通过统一帮助说明提供；
- 无数据时展示明确空态，不伪造明细或趋势。

#### FR-022.12：时间范围统计

用户可以选择开始日期和结束日期查看范围内的统计数据。

**Consequences (testable):**

- 开始日期和结束日期均包含在统计范围内；
- 后台按 Asia/Shanghai 自然日解释日期边界，底层存储时区不改变展示口径；
- 统计结果至少包含点击次数和去重点击人数；
- 支持按入口筛选；
- 开始日期晚于结束日期时阻止查询并提示原因。

#### FR-022.13：趋势与点击明细

报表提供按日趋势和脱敏点击明细。

**Consequences (testable):**

- 趋势可按日展示点击次数和点击人数；
- 明细至少包含入口、点击时间、配置版本、跳转结果和脱敏用户标识；
- 明细筛选条件与汇总筛选条件一致；
- 明细中的用户标识不展示完整敏感信息；
- 无权限用户不能访问明细。

#### FR-022.14：数据导出

具有导出权限的用户可以导出当前筛选条件下的汇总或明细数据。

**Consequences (testable):**

- 导出内容与当前入口、时间范围和数据类型筛选一致；
- 导出文件包含查询口径、生成时间和筛选条件；
- 明细导出继续遵守用户标识脱敏规则；
- 导出操作记录操作人、时间、筛选条件和结果；
- 导出失败提供可理解的错误反馈，不生成不完整文件。

### 5.5 权限、审计与数据治理

**Description:** 金刚区配置和数据报表包含运营控制与用户行为数据，需要复用现有后台权限，并保留最小必要的审计和保留规则。

#### FR-022.15：权限隔离

系统按照现有运营后台角色控制配置、查看报表和导出明细的权限。

**Consequences (testable):**

- 无配置权限的用户不能保存、删除或恢复入口；
- 无报表权限的用户不能访问金刚区数据页面；
- 无导出权限的用户看不到或不能使用导出操作；
- 权限拒绝不泄露明细数据。

#### FR-022.16：操作审计

系统记录配置保存、删除、恢复、报表查询和导出操作。

**Consequences (testable):**

- 审计记录至少包含操作人、操作时间、操作类型、对象 ID、变更摘要和结果；
- 审计记录不可由普通运营人员修改；
- 恢复配置能够关联到被恢复的历史版本。

## 6. Non-Goals (Explicit)

- 不建设草稿、发布、审批或多版本预览流程；保存即生效。
- 不在 FR-022 内改造 Banner、榜单、找项目、动态、OPC 服务机构或今日路径的配置能力。
- 不统计入口曝光量和点击率，除非另开需求明确加入曝光事件。
- 不支持匿名用户跨设备识别或匿名点击人数去重。
- 不建设人群定向、AB 实验、个性化排序或策略推荐。
- 不允许后台配置任意 URL、脚本或未授权外部域名。
- 不在本 PRD 中规定具体 REST/gRPC 路径、数仓技术或前端框架。

## 7. MVP Scope

### 7.1 In Scope

- C 端首页 Banner 后的金刚区宫格展示和跳转。
- 后台入口基础信息、排序、启停、有效期和即时生效保存。
- 有效跳转目标校验、配置审计和上一份有效配置恢复。
- 点击事件上报、事件幂等、点击次数累计和登录用户去重人数。
- 后台累计统计、时间范围统计、入口筛选、按日趋势、脱敏明细和导出。
- 复用现有运营后台权限体系。

### 7.2 Out of Scope for MVP

- 草稿/发布/审批工作流：本期采用保存即生效，减少运营链路和状态复杂度。
- 曝光、点击率、转化率和跳转后业务结果统计：需要另定义曝光及跨页面归因模型。
- 人群定向、AB 实验和个性化推荐：入口编排先采用统一配置。
- 匿名用户识别：第一期仅统计登录用户。
- 超大规模异步导出和下载中心：导出格式、行数上限和异步策略待架构阶段确认。

## 8. Success Metrics

**Primary**

- **SM-1：配置生效时效** — 合法配置保存成功后，首页在约定缓存刷新窗口内展示新配置；目标为 99% 的保存操作在 1 分钟内可见。验证 FR-022.4～FR-022.6。
- **SM-2：统计准确性** — 抽样核对原始幂等事件、点击次数和按 `entryId + userId + 时间范围` 去重人数，统计结果无重复计数和漏计。验证 FR-022.8～FR-022.10。
- **SM-3：报表可用性** — 具有权限的运营人员可以在默认累计视图和自选时间范围视图完成查询，并成功导出当前筛选结果；目标为关键路径一次通过率 ≥95%。验证 FR-022.11～FR-022.14。

**Secondary**

- **SM-4：金刚区入口使用** — 上线后可按入口获得稳定的点击次数和去重点击人数数据，为后续入口排序复盘提供依据。验证 FR-022.8～FR-022.10。
- **SM-5：配置操作可追溯** — 100% 的保存、删除、恢复和导出操作有审计记录。验证 FR-022.6、FR-022.14、FR-022.16。

**Counter-metrics (do not optimize)**

- **SM-C1：入口数量** — 不以增加入口数量为目标，避免金刚区挤压首页核心内容和造成选择负担。反向约束 FR-022.1、FR-022.3。
- **SM-C2：点击次数** — 不通过诱导性文案或误触布局单独追求点击次数，点击数据必须与真实有效跳转行为一致。反向约束 FR-022.2、FR-022.8。

## 9. Open Questions

1. 金刚区入口上限是否固定为 8 个，还是允许后台配置上限？产品负责人；进入 UX 规格前确认。
2. 图标的上传格式、尺寸、大小限制和是否支持图标库选择是什么？产品/UX；进入后台配置设计前确认。
3. 导出格式是否同时支持 CSV 和 XLSX，单次最大行数是多少？数据/架构；进入架构设计前确认。
4. 大数据量导出是否需要异步任务和下载中心？数据/架构；以预估数据量和现有平台能力为准。
5. 明细数据保留周期和用户标识脱敏规则是否复用现有埋点平台规范？数据/安全；进入数据方案前确认。
6. 累计值的起始时间采用统计系统启用时间，还是每个入口首次生效时间？产品/数据；报表验收前确认。

## 10. Assumptions Index

- `[ASSUMPTION: 首页模块顺序]` 金刚区放在 Banner 后、三格数据前；该位置基于现有截图和 FR-021 首页信息层级建议，需在 UX 评审中确认。
- `[ASSUMPTION: 布局]` 第一版采用 4 列、最多 8 个入口的宫格布局；入口上限仍是开放问题。
- `[ASSUMPTION: 登录态]` FR-021 的 C 端默认已登录，因此第一期点击人数只按 `userId` 去重，不纳入匿名用户。
- `[ASSUMPTION: 时区]` 报表日期按 Asia/Shanghai 自然日解释，事件底层按 UTC 存储；如现有数据平台有统一时区规范，以平台规范为准。
- `[ASSUMPTION: 缓存窗口]` 保存即生效允许存在约定的缓存刷新窗口；具体分钟数由架构阶段结合现有 BFF 缓存能力确定。
- `[ASSUMPTION: 导出]` 导出默认遵守当前筛选条件和脱敏规则；格式、行数上限和异步策略尚未确定。
