# Correct Course 变更提案：FR-022 首页金刚区

## 1. 变更结论

本需求独立编号为 **FR-022**，使用分支 `fr-022-home-jingang` 推进，不修改 FR-021 的定稿合同。FR-022 包含首页金刚区、后台即时生效配置、点击统计、详细报表和数据导出。

附件截图仅作为当前首页视觉参考，不作为文案、金额、榜单、动态或配置内容的需求来源。

## 2. 首页结构

建议首页顺序为：

```text
顶栏 → Banner → 金刚区 → 三格数据 → 新手学院/活动中心
→ 设置工作台 → 榜单 → 找项目 → 右豹动态 → OPC 服务机构 → Footer
```

金刚区放在 Banner 后、三格数据前；不并入 Banner，不与今日路径气泡合并。FR-021 其余首页模块顺序保持不变。

## 3. 产品范围

### FR-022.1 C 端展示与跳转

首页按后台下发的有效配置展示入口，至少包含图标、标题、跳转类型和跳转参数，并按配置排序。

- 仅展示启用且处于有效时间内的入口；
- 配置为空或所有入口无效时，金刚区整体隐藏；
- 跳转目标失效、无权限或打开失败时给出统一反馈；
- 金刚区异常不阻塞首页其他模块；
- 站内路由和外部链接使用白名单校验。

### FR-022.2 后台配置

运营可新增、编辑、删除、排序和启停金刚区入口。**保存配置后立即生效，不建设草稿、发布、审核或预览版本流程。**

建议字段：`entryId`、图标、标题、副标题、跳转类型、跳转参数、排序、启用状态、生效时间、失效时间、更新时间、更新人。

即时生效约束：

- 保存原子提交，不能出现文案已更新但跳转参数未更新的半配置状态；
- 保存成功返回生效版本号或更新时间；
- BFF 缓存主动失效或使用短 TTL，避免长期展示旧配置；
- 保留操作审计日志，并支持恢复上一份有效配置。

### FR-022.3 点击统计

每个入口上报有效点击事件：

- 点击次数：每次有效点击累计；
- 点击人数：按登录用户 `userId` 去重；
- 客户端重试通过 `eventId` 幂等，避免次数虚增；
- 跳转失败仍计入点击，同时记录 `jumpResult=failed`；
- 未登录用户第一期不纳入点击人数，避免匿名 ID 与登录 ID 混用。

建议事件字段：`eventId`、`entryId`、`configVersion`、`userId`、`source=home_jingang`、`position`、`clickTime`、`jumpType`、`jumpResult`。

### FR-022.4 统计报表与导出

后台提供详细数据报表页面：

- 默认展示累计点击次数和累计去重点击人数；
- 支持选择时间范围，展示范围内的点击次数和去重点击人数；
- 支持入口维度汇总：入口名称、入口 ID、点击次数、点击人数；
- 支持按日查看点击次数和点击人数趋势；
- 支持查看点击明细：用户标识脱敏、入口、点击时间、配置版本、跳转结果；
- 支持导出当前筛选条件下的汇总或明细数据。

时间口径建议：后台按 Asia/Shanghai 的自然日解释范围，底层事件按 UTC 存储。点击人数按 `entryId + userId + 统计时间范围` 去重。

## 4. UX 建议

- 第一版使用紧凑宫格，不做轮播；建议 4 列，最多 8 个入口；
- 标题最多一行，副标题可选且最多一行；入口高度固定；
- 空配置、加载失败时隐藏金刚区，不展示空壳；
- 保存按钮反馈“已保存并生效”，明确无需再次发布；
- 图标入口提供可读的无障碍名称，不能只依赖图形。

## 5. 架构与能力契约

现有 `创作者首页` 能力新增 `quickEntries[]`：

```text
quickEntries[] {
  entryId,
  configVersion,
  icon,
  title,
  subtitle,
  jumpType,
  jumpTarget,
  sort
}
```

新增能力：

| 能力 | 调用方 | 结果 |
| --- | --- | --- |
| 首页金刚区配置保存 | Admin | 保存后立即生效的配置与版本号 |
| 首页金刚区点击上报 | C 端 | 幂等接收事件 |
| 首页金刚区统计查询 | Admin | 累计或时间范围汇总、趋势、明细 |
| 首页金刚区数据导出 | Admin | 当前筛选条件下的汇总/明细文件 |

建议模型拆分为 `HomeQuickEntry`（当前配置）、`HomeQuickEntryAudit`（保存审计）、`HomeQuickEntryClickEvent`（原始事件），统计由聚合查询或数仓投影计算，不在配置表直接累加人数。

## 6. Epic 建议

新增 Epic：**首页金刚区配置与点击分析**。

1. C 端展示金刚区与跳转；
2. 后台即时生效配置；
3. 点击事件上报与幂等；
4. 累计/时间范围统计与趋势；
5. 明细报表与数据导出；
6. 失效配置、跳转失败、缓存延迟和权限验收。

## 7. 风险与验收重点

| 风险 | 控制措施 |
| --- | --- |
| 即时生效导致误配置直接线上可见 | 保存前校验、操作审计、保留上一版本恢复能力 |
| 缓存导致保存后未立即看到 | 版本号 + 主动失效/短 TTL |
| 重试造成点击次数虚高 | `eventId` 幂等 |
| 点击人数口径不一致 | 固定 `entryId + userId + 时间范围` 去重 |
| 明细导出泄露用户信息 | 用户标识脱敏、角色权限和导出审计 |
| 任意外链带来安全风险 | 跳转类型白名单和域名校验 |

## 8. 后续需在 PRD/架构阶段闭合的细节

- 入口上限是否固定为 8 个；
- 图标格式、尺寸和大小限制；
- 导出格式（CSV/XLSX）及单次最大行数；
- 大数据量导出是否使用异步任务和下载中心；
- 报表权限是否复用现有运营后台角色；
- 明细保留周期和用户标识脱敏规则；
- 累计起始时间采用统计系统启用时间，还是每个入口首次生效时间。
